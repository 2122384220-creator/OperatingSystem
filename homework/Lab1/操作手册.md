# Lab1 安装手册：VMware 与 Ubuntu 虚拟机

## 一、实验背景

本课程的实验需要在 Linux 系统中编译 C 程序、观察进程与内存、查看文件与文件系统。直接在自己的 Windows 主机上做这些操作不现实，也不安全：

- Windows 和 Linux 的命令体系不同，本课程用到的 `gcc`、`make`、`gdb`、`ps`、`ls` 等命令都以 Linux 为准；
- 操作系统实验会反复创建进程、修改系统配置、清理文件，误操作可能影响自己的日常电脑；
- 万一环境被改坏，Linux 虚拟机可以直接删除重装，Windows 主机不能。

虚拟机的作用就是在一台真实电脑里再运行一台“虚拟电脑”。你可以把 Ubuntu 安装在虚拟机中，像使用一台独立 Linux 主机一样操作它；即使编译报错、程序跑飞、配置写错，也不会破坏宿主机。

本实验最终要得到一台能够正常启动、联网、打开终端、并按要求装好课程所需软件的 Ubuntu 虚拟机。第一次实验不写代码、不编译程序，先把环境搭好；后面的实验会在这台虚拟机上编译和调试 C 程序。

## 三、宿主机要求与虚拟机配置

开始前先确认自己的电脑满足以下要求：

| 项目 | 最低要求 | 建议配置 |
| :--- | :--- | :--- |
| 操作系统 | Windows 10/11 64 位 | Windows 11 64 位 |
| 内存 | 8GB | 16GB 或以上 |
| 磁盘剩余空间 | 40GB | 80GB 或以上 |
| CPU | 支持虚拟化 | Intel VT-x 或 AMD-V 已开启 |
| 网络 | 可访问互联网 | 安装和更新软件包会用到 |

### 根据宿主机选择虚拟机配置

先在 Windows 的“任务管理器 → 性能”中查看宿主机的 CPU 核心数和内存，再在“此电脑”中查看存放虚拟机的磁盘剩余空间。按下表选择与自己宿主机匹配的档位：

| 宿主机情况 | 虚拟 CPU 总核心数 | 虚拟内存 | 虚磁盘上限 | 适用说明 |
| :--- | :---: | :---: | :---: | :--- |
| 8GB 内存，4 核左右，剩余 50GB 以上 | 2 核 | 4096MB | 40GB | 最低可用档；做实验时关闭宿主机上不必要的程序 |
| 16GB 内存，6 核以上，剩余 80GB 以上 | 2 核 | 6144MB | 60GB | **课程推荐档**；编译和调试都比较流畅 |
| 32GB 及以上内存，8 核以上，剩余 120GB 以上 | 4 核 | 8192MB | 80GB | 宽裕档；适合长期保留多个快照 |

> **选择规则**：宿主机同时满足该行的内存、CPU 和磁盘条件时，才选择该档。任意一项不满足时，选低一档。不要把宿主机的全部 CPU 或内存分给虚拟机，否则 Windows 和虚拟机都会变卡。

虚磁盘默认按实际使用量逐步增长，将上限设为 60GB 或 80GB 不代表创建时立即占用同等大小。但 VMware 快照会额外占用宿主机空间，学期内应定期检查剩余空间。

### 检查 CPU 虚拟化

1. 在 Windows 中按 `Ctrl + Shift + Esc` 打开任务管理器。
2. 点击 **性能**。
3. 选择 **CPU**。
4. 查看右下角是否显示 **虚拟化：已启用**。

如果显示 **虚拟化：已禁用**，需要进入 BIOS/UEFI 开启 Intel VT-x、Intel Virtualization Technology、AMD-V 或 SVM Mode。不同品牌电脑入口不同，常见按键是 `F2`、`F10`、`F12`、`Del` 或 `Esc`。

## 五、创建 Ubuntu 虚拟机

### 步骤 1：新建虚拟机

1. 打开 VMware Workstation Pro。
2. 点击 **Create a New Virtual Machine**。
3. 选择 **Typical (recommended)**。
4. 点击 **Next**。

### 步骤 2：选择 Ubuntu 镜像

1. 选择 **Installer disc image file (iso)**。
2. 点击 **Browse**。
3. 选择保存好的 `ubuntu-24.04.4-desktop-amd64.iso`。
4. 点击 **Next**。

如果 VMware 识别出 Ubuntu，并提示 Easy Install，可以继续；如果没有识别，也不影响，后面进入 Ubuntu 安装界面手动安装即可。

### 步骤 3：填写虚拟机信息

建议填写：

| 项目 | 建议值 |
| :--- | :--- |
| Full name | `姓名拼音` |
| User name | `姓名拼音` |
| Password | 自己能记住的密码 |
| Virtual machine name | `Ubuntu-24.04-OSLab` |
| Location | 保持默认，或选择剩余空间充足的磁盘 |

> **注意**：用户名建议只使用小写字母和数字，不要使用中文、空格或特殊符号。后面写 C 代码和用 `gcc`、`make` 时，路径中有中文会带来不必要的麻烦。

### 步骤 4：设置磁盘

1. 根据第三节的宿主机档位，磁盘大小填写 **40GB、60GB 或 80GB**。
2. 选择 **Store virtual disk as a single file** 或 **Split virtual disk into multiple files** 都可以。
3. 点击 **Next**。

说明：

- 这里填写的是虚磁盘上限，不代表立刻占用同等大小的宿主机空间。
- 如果经常复制虚拟机文件，选择 split 更方便。
- 如果追求性能和文件整洁，选择 single file 更简单。

### 步骤 5：自定义硬件

在最后确认页点击 **Customize Hardware**，根据第三节选定的档位设置。下表为课程推荐档：

| 硬件 | 建议值 |
| :--- | :--- |
| Memory | 6144 MB；宿主机只有 8GB 内存时改为 4096MB |
| Processors | 2 个核心 |
| Network Adapter | NAT |
| CD/DVD | 使用 `ubuntu-24.04.4-desktop-amd64.iso` |
| Display | 保持默认 |

设置完成后点击 **Close**，再点击 **Finish**。

> VMware 可能将 CPU 分成 **Number of processors** 和 **Number of cores per processor** 两项。本课程建议前者设为 `1`，2 核档将后者设为 `2`，4 核档将后者设为 `4`。两者相乘才是 Ubuntu 中 `nproc` 看到的总核心数。

## 六、安装 Ubuntu

### 步骤 1：启动虚拟机

1. 选中刚创建的 `Ubuntu-24.04-OSLab`。
2. 点击 **Power on this virtual machine**。
3. 等待进入 Ubuntu 安装界面。

如果出现黑屏或卡住，先等 2～3 分钟；仍无响应再关闭虚拟机重新启动。

### 步骤 2：选择安装语言

建议选择：

- 语言：**English**
- 键盘：**English (US)**

说明：系统界面可以使用英文，遇到报错、命令输出、编译错误时更容易搜索和对照。

### 步骤 3：选择安装方式

在 Ubuntu 安装器中按以下选择：

1. 选择 **Install Ubuntu**。
2. 选择 **Interactive installation**。
3. 应用集合选择 **Default selection**。
4. 第三方软件可暂时不勾选。
5. 磁盘设置选择 **Erase disk and install Ubuntu**。

> **重要**：这里擦除的是虚拟机里的虚拟磁盘，不是 Windows 真实硬盘。只要你是在 VMware 虚拟机窗口里操作，就不会格式化宿主机磁盘。

### 步骤 4：创建用户

建议：

| 项目 | 建议值 |
| :--- | :--- |
| Your name | `姓名拼音` |
| Your computer's name | `随意` |
| Pick a username | `姓名拼音` |
| Password | 自己能记住的密码 |
| Require my password to log in | 勾选 |

### 步骤 5：选择时区并安装

1. 时区选择 **Shanghai**。
2. 点击 **Install**。
3. 等待安装完成，通常需要 10～30 分钟。
4. 提示重启时点击 **Restart Now**。
5. 如果提示移除安装介质，直接按 `Enter`。

## 七、安装后的基础检查

登录 Ubuntu 后，按 `Ctrl + Alt + T` 打开终端。下面的检查请**一条一条执行**，每执行一条就先看清它的输出，再执行下一条。不要把所有命令一次性粘贴进终端，否则输出会混在一起，看不出是哪条命令出了问题。

### 检查 1：确认 Ubuntu 版本

```bash
cat /etc/os-release
```

期望在输出中看到 `PRETTY_NAME="Ubuntu 24.04.x LTS"`。安装后如果执行过系统更新，小版本号可能高于 `24.04.4`，这属于正常现象。

### 检查 2：确认主机名

```bash
hostname
```

期望输出 `ubuntu`，或者你在安装时为计算机填写的名称。

### 检查 3：确认 CPU 核心数

```bash
nproc
```

期望输出与第三节选定的档位一致，即 `2` 或 `4`。

### 检查 4：确认内存

```bash
free -h
```

看 `Mem` 行的 `total` 列。显示值会略小于 VMware 中设置的数值，因为一部分内存被固件和内核占用：4GB 档约显示 `3.8Gi`，6GB 和 8GB 档同样会略小于设置值。

### 检查 5：确认根分区容量

```bash
df -h /
```

看 `Size` 列。容量可能略小于选定的 40GB、60GB 或 80GB 虚磁盘上限，属于正常现象。

### 检查 6：确认 IP 地址

```bash
ip addr
```

期望在 `ens33`（或类似名称）的网卡下看到一个以 `192.168`、`172` 或 `10` 开头的 IPv4 地址。只有 `lo` 回环网卡的 `127.0.0.1` 说明虚拟机还没有拿到 IP。

### 检查 7：测试 IP 联通性

```bash
ping -c 4 223.5.5.5
```

能看到 4 行返回时间，说明虚拟机可以通过 NAT 访问外部网络。

### 检查 8：测试 DNS 解析

```bash
ping -c 4 mirrors.tuna.tsinghua.edu.cn
```

能解析出 IP 并看到返回时间，说明 DNS 解析和域名访问都正常。

这里只是借一个公网域名验证解析，**不代表你需要更换软件源**——软件源默认用官方源即可，详见第八节。

> `ping` 默认会一直运行，`-c 4` 表示只发送 4 个包后自动停止。如果忘记加 `-c` 参数，按 `Ctrl + C` 可以随时停止。

## 八、关于软件源（默认不需要修改）

Ubuntu 装好之后默认使用官方软件源（`archive.ubuntu.com`），**本实验不要求更换软件源**，直接进入第九节安装组件即可。报告与验收里的软件源一栏，用官方源还是国内镜像站都算合格，不影响任何验收项。

只有出现下面两种情况时，才需要换成国内镜像站，做法见文末 **附录十四：配置国内软件源（可选）**：

- `sudo apt update` 或 `sudo apt install` 长时间没有进度、下载速度明显很慢；
- 报 `Could not resolve`、`Connection timed out` 之类的网络错误，但第七节的联网检查全部正常。

换源只是加速手段。如果 `apt` 命令一直卡着不动，可以按 `Ctrl + C` 中断（不会损坏系统），换源之后重新执行；万一之后提示 `dpkg` 被中断，先执行 `sudo dpkg --configure -a` 恢复再重试。

## 九、安装课程必需组件

本课程要求安装 VMware Tools、终端编辑器 vim、OpenSSH 服务端和一套 C 开发工具链：

- **VMware Tools**：改善分辨率、自适应窗口、复制粘贴和鼠标体验，做实验时窗口能跟着调整会方便很多。
- **build-essential**：C 编译工具集，提供 `gcc`、`make` 和标准库头文件。本课程后面要编译运行 C 程序，缺了它 `gcc` 命令会直接找不到。第一次实验不编译，但先装好，后面实验不用再补。
- **gdb**：C 调试器。程序结果不符合预期时，用它逐行观察比反复加 `printf` 更省时间。
- **git**：版本控制工具。本课程要求在本地仓库中提交作业，虚拟机里也要能执行 `git` 命令。
- **manpages-dev**：系统调用和 C 库函数的手册页，例如 `man 2 fork`。阅读 `fork`、`exec`、`open` 的返回值时比查网页更准确。
- **vim**：终端里的文本编辑器。本课程的实验都在终端里完成，写 C 代码、改配置文件都用它；第十节就要用 vim 创建并保存一个文件。
- **openssh-server**：SSH 服务端。装好之后这台虚拟机可以被宿主机或其它机器通过 SSH 登录，后面观察进程、网络和登录行为时会用到。

本节命令直接用官方源执行即可，不需要先换源。如果下载确实很慢或者一直卡着不动，按文末 **附录十四** 换成国内镜像站后再执行。

### 步骤 1：安装软件包

```bash
sudo apt install -y open-vm-tools open-vm-tools-desktop build-essential gdb git manpages-dev vim openssh-server
```

`apt install` 会把列出的软件包连同它们的依赖一次装好，`-y` 表示自动回答 yes，不再逐条确认。

装完之后让 SSH 服务开机自启并立即启动：

```bash
sudo systemctl enable --now ssh
```

`enable` 是设置开机自动启动，`--now` 是同时立刻启动，两件事一条命令完成。Ubuntu 24.04 的 SSH 默认由 `ssh.socket` 按需激活，执行完这一步，22 端口就会进入监听状态。

### 步骤 2：重启虚拟机

```bash
sudo reboot
```

VMware Tools 的桌面集成功能需要重启后才会生效。

### 步骤 3：逐条验证

重启并重新登录后，打开终端，同样**一条一条执行**下面的命令：

**验证 1：VMware Tools 版本**

```bash
vmware-toolbox-cmd -v
```

期望输出一个版本号，例如 `12.x.x.xxxxx (build-xxxxxxx)`。

**验证 2：`open-vm-tools` 服务是否在运行**

```bash
systemctl is-active open-vm-tools
```

期望输出 `active`。

**验证 3：C 编译器版本**

```bash
gcc --version
```

期望输出形如 `gcc (Ubuntu ...) 13.x.x` 的一行版本信息。

**验证 4：make 版本**

```bash
make --version
```

期望输出形如 `GNU Make 4.x` 的一行版本信息。

**验证 5：gdb 版本**

```bash
gdb --version
```

期望输出形如 `GNU gdb (Ubuntu ...) 15.x` 的一行版本信息。

**验证 6：git 版本**

```bash
git --version
```

期望输出形如 `git version 2.x.x` 的一行版本信息。

**验证 7：确认软件包都已安装**

```bash
dpkg-query -W -f='${Package}\t${Version}\n' open-vm-tools build-essential gdb git manpages-dev vim openssh-server
```

期望每行都输出各自的已安装版本号。某一行没有版本号或提示未安装，说明该软件包缺失。

**验证 8：vim 是否可用**

```bash
vim --version
```

期望第一行形如 `VIM - Vi IMproved 9.1`。如果提示 `command not found`，或者版本行里带 `Small version`（说明装的是精简版 `vim-tiny`，功能不全），执行下面这条命令换成完整版：

```bash
sudo apt install -y vim
```

**验证 9：SSH 服务端是否已安装并在监听 22 端口**

```bash
ssh -V
```

注意这里是大写字母 `V`，查的是 SSH **客户端**的版本，期望输出形如 `OpenSSH_9.6p1`。

```bash
ss -lnt | grep ':22'
```

期望看到一行包含 `LISTEN` 和 `:22` 的输出，说明本机正在监听 SSH 的默认端口。`ss` 用来查看套接字状态：`-l` 只看处于监听（LISTEN）的套接字，`-n` 表示直接显示端口数字不做服务名解析，`-t` 表示只看 TCP。

### 步骤 4：验证 VMware Tools 桌面功能

用鼠标拖动 VMware 虚拟机窗口的边缘改变窗口大小。如果 Ubuntu 桌面分辨率能跟着自动适配，说明 VMware Tools 的桌面集成功能正常。

### 验收标准汇总

| 组件 | 验收标准 |
| :--- | :--- |
| VMware Tools | `vmware-toolbox-cmd -v` 输出版本号，`open-vm-tools` 状态为 `active`，窗口缩放时分辨率自动适配 |
| build-essential | `gcc --version` 与 `make --version` 都能输出版本信息 |
| gdb | `gdb --version` 能输出版本信息 |
| git | `git --version` 能输出版本信息 |

## 十、用 vim 编写并保存第一个文件

软件装好之后，用终端编辑器 vim 创建并保存一个文件，确认“打开编辑器 → 输入内容 → 保存退出 → 读回文件”这条链路是通的。本课程后面的实验都在终端里完成，写 C 代码、改配置文件都靠 vim，先在这份最简单的文件上把操作练熟。

### 步骤 1：建立实验目录

```bash
mkdir -p ~/oslab/Lab1
cd ~/oslab/Lab1
```

`mkdir -p` 表示逐级创建目录，目录已经存在时也不报错；`cd` 切换到刚建好的目录。后面本实验用到的练习文件都放在这里，避免和系统文件混在一起。

### 步骤 2：用 vim 创建 hello.txt

```bash
vim hello.txt
```

`vim` 和记事本不一样：它有好几种模式，打开文件后默认停在**普通模式**，这时敲字母不会插入文字，而是被当成命令。整个流程只有四步：

| 步骤 | 按键 | 作用 |
| :--- | :--- | :--- |
| ① 进入编辑 | `i` | 左下角出现 `-- INSERT --`，此后输入的字符才会写进文件 |
| ② 输入内容 | 直接打字 | 按下表内容输入，注意中英文标点不要混用 |
| ③ 回到普通模式 | `Esc` | 左下角的 `-- INSERT --` 消失，表示已经退出编辑 |
| ④ 保存并退出 | `:wq` 再按回车 | `w` 是写入（write），`q` 是退出（quit） |

> **常见卡壳**：`Esc` 可以多按一两次，确认左下角的 `-- INSERT --` 已经消失，再输入 `:wq`。如果不小心按错了，输入 `:q!` 再回车表示不保存强制退出，回到终端重新执行 `vim hello.txt` 即可。

在文件里输入下面的内容，把学号和姓名换成自己的：

```text
操作系统 Lab1 环境验收
学号：2026333001
姓名：朱泽科
本文件由本人在 Ubuntu 24.04 虚拟机中使用 vim 创建并保存。
```

> **注意**：`hello.txt` 只是用来练 vim 的练习文件，**本作业不需要提交它**。请把它建在虚拟机的 `~/oslab/Lab1` 目录里，不要复制进仓库的提交目录——提交目录里多放一个文件就会导致 PR 检查不通过。内容写成自己的学号和姓名即可，不必写 Markdown 的 `#` 标题或 `*` 列表。

### 步骤 3：确认文件已经保存

```bash
cat hello.txt
```

`cat` 把文件内容原样打印到屏幕上。期望看到的内容和刚才输入的一致，其中学号和姓名是自己的。如果显示为空或内容不全，说明第 ④ 步没有真正写入，重新执行 `vim hello.txt`，按 `i` 补全内容后再按 `Esc` 和 `:wq`。

```bash
ls -l hello.txt
```

期望列出一个文件，并且大小不为 0。`-l` 表示长格式显示，能看到权限、属主、大小和最后修改时间。

### 步骤 4：再打开一次，熟悉 vim 的按键（选做）

```bash
vim hello.txt
```

这次不输入任何内容，只用 `j`、`k` 上下移动光标，最后输入 `:q` 加回车退出——没有改动过内容时，单独用 `q` 就能退出。这一步是为了体会“普通模式下按键是命令”的感觉，**不要求**出现在 Lab1 报告中。

### 创建课程基线快照

安装和工具链配置全部完成后，关闭 Ubuntu，在 VMware 中创建一个名为 `Lab1-ready` 的快照。该快照是干净的课程基线：后面实验如果把环境改坏，可以回到这个状态重来。

## 十一、常见问题

遇到问题时，不要只反复执行 Lab1 中的验收命令。先按下面对应小节修复，再回到 Lab1 重新验证。

### 问题 1：`gcc: command not found`

说明 `build-essential` 没有装上。先确认软件包状态：

```bash
dpkg-query -W build-essential
```

如果提示没有安装，执行：

```bash
sudo apt update
```

```bash
sudo apt install -y build-essential
```

装完再验证：

```bash
gcc --version
```

### 问题 2：`vim: command not found`，或者 vim 打开后功能不全

说明完整版 vim 没有装上。Ubuntu 桌面版出厂只带精简版 `vim-tiny`，它的功能有限，装完整版即可：

```bash
sudo apt update
```

```bash
sudo apt install -y vim
```

第一条刷新软件包索引，第二条安装完整版 vim。装完再验证：

```bash
vim --version
```

第一行应显示 `VIM - Vi IMproved` 和版本号，并且不再带 `Small version`。

### 问题 3：`make: command not found` 或 `gdb: command not found`

这两个命令分别由 `make` 和 `gdb` 提供。检查并补装：

```bash
dpkg-query -W make gdb
```

```bash
sudo apt install -y build-essential gdb
```

### 问题 4：在 vim 里退不出来，或者内容没保存

这是新手最容易卡住的一步。vim 打开后默认停在普通模式，如果一直没按 `i`，你输入的内容会被当成命令执行，屏幕看起来就会“乱掉”。按下面的顺序收拾：

1. 先按几次 `Esc`，直到左下角的 `-- INSERT --` 消失。
2. 想保存：输入 `:wq` 再加回车；不想保存：输入 `:q!` 再加回车。
3. 如果输入 `:` 之后看不到底部的命令行，说明还没回到普通模式，再按一次 `Esc` 重来。
4. 退出后用 `cat hello.txt` 确认内容是否真的写进去了。

实在退不出来，可以按 `Ctrl + Z` 把 vim 挂到后台，再执行 `kill %1` 结束它，然后重新执行 `vim hello.txt`。

### 问题 5：`/var/log/installer/media-info` 不存在或没有读取权限

读取安装介质信息需要管理员权限，命令要带 `sudo`：

```bash
sudo cat /var/log/installer/media-info
```

如果这个文件确实不存在（例如用的是非官方镜像或安装方式不同），在报告的任务二表格中如实注明“该文件不存在”，不要编造内容。Ubuntu 版本和架构仍以 `cat /etc/os-release` 与 `uname -m` 的输出为准。

### 问题 6：虚拟机没有 IP 或无法联网

1. 关闭虚拟机，在 VMware 的 **VM → Settings → Network Adapter** 中选择 **NAT**，并勾选 **Connected** 和 **Connect at power on**。
2. 启动 Ubuntu 后查看网卡状态：

```bash
nmcli device status
```

3. 如果网卡显示 `disconnected`，先重启 Ubuntu 网络服务：

```bash
sudo systemctl restart NetworkManager
```

4. 再次执行 `hostname -I`、`ip route` 和 `ping -c 4 223.5.5.5`。能 ping IP 但不能 ping 域名时，是 DNS 问题；IP 和域名都不通时，先检查 NAT 和宿主机网络。

### 问题 7：`apt update` 或安装软件失败

- 显示 `Could not resolve`：DNS 或网络未通，先按“问题 6”处理。
- 下载很慢或超时：按文末 **附录十四** 换成国内镜像站；官方源能正常下载时不需要换。
- 换成镜像站后显示找不到仓库：Ubuntu 24.04 的 `Suites` 必须是 `noble`，并检查镜像地址是否拼错。
- 显示签名验证失败：不要跳过签名检查，用附录十四里的备份还原，再重新配置 `Signed-By` 行。
- 修改 `/etc/apt/sources.list` 后没生效：Ubuntu 24.04 要修改的是 `/etc/apt/sources.list.d/ubuntu.sources`。
- 显示 `Could not get lock`：先关闭“软件更新器”，等待另一个 `apt` 任务完成后重试，不要直接删除锁文件。

### 问题 8：VMware Tools 没有安装，或窗口不能自动缩放

Ubuntu 应使用软件源中的 `open-vm-tools`，不需要在 VMware 菜单中挂载旧式 VMware Tools 光盘。先安装服务和桌面集成组件：

```bash
sudo apt update
```

```bash
sudo apt install -y open-vm-tools open-vm-tools-desktop
```

重启服务和虚拟机：

```bash
sudo systemctl restart open-vm-tools
```

```bash
sudo reboot
```

重启登录后验证：

```bash
vmware-toolbox-cmd -v
```

```bash
systemctl is-active open-vm-tools
```

第一条应输出版本号，第二条应输出 `active`。如果仍不能随窗口改变分辨率：

1. 在 VMware 菜单中选择 **View → Autosize → Autofit Guest**。
2. 确认已登录进入 Ubuntu 桌面，而不是停留在登录界面。
3. 执行 `dpkg-query -W open-vm-tools-desktop`，确认桌面组件已安装。
4. 仍有问题时，执行 `sudo apt install --reinstall -y open-vm-tools open-vm-tools-desktop`，然后再次重启。

如果 VMware 菜单中 **Install VMware Tools** 是灰色，但上面两条验证命令正常，不需要处理；Ubuntu 已通过 `open-vm-tools` 提供同等功能。

如果只是复制粘贴或拖放不生效，关闭虚拟机后打开 **VM → Settings → Options → Guest Isolation**，勾选 **Enable copy and paste** 和 **Enable drag and drop**，然后重新启动虚拟机。

### 问题 9：SSH 装好了却连不上，或提示 `Unit ssh.service could not be found`

先确认服务端软件包是否装上——`ssh` 客户端和 `openssh-server` 服务端不是一回事，能执行 `ssh` 命令不代表本机可以接受 SSH 连接：

```bash
dpkg-query -W openssh-server
```

没有输出版本号就补装：

```bash
sudo apt update
```

```bash
sudo apt install -y openssh-server
```

再确认 22 端口是否在监听：

```bash
ss -lnt | grep ':22'
```

Ubuntu 24.04 的 SSH 默认由 `ssh.socket` 按需激活，所以 `systemctl is-active ssh` 显示 `inactive` 是正常的，不代表服务不可用；只要上面能看到 22 端口处于 `LISTEN`，就说明 SSH 服务端已经就绪。想让它开机自启可以执行：

```bash
sudo systemctl enable ssh
```

后面从宿主机登录这台虚拟机时，用 `ssh Ubuntu用户名@Ubuntu的IP地址` 连接，密码就是安装 Ubuntu 时设置的那个。

### 其他常见问题

| 现象 | 可能原因 | 处理 |
| :--- | :--- | :--- |
| VMware 提示不支持虚拟化 | BIOS/UEFI 中未开启虚拟化 | 开启 Intel VT-x / AMD-V / SVM Mode |
| 创建虚拟机后很卡 | 分配内存太少或宿主机内存不足 | 虚拟机至少分配 4GB；关闭宿主机不必要的程序 |
| 忘记 Ubuntu 密码 | 无法使用 `sudo` 或登录 | 刚建好且没有重要数据时，重新安装虚拟机最省时间 |
| 鼠标被虚拟机捕获 | VMware 正常行为 | 按 `Ctrl + Alt` 释放鼠标 |
| 误选中文用户名 | 路径和命令输入可能不方便 | 刚建好时建议重新创建英文小写用户名 |
| 终端里粘贴的 `sudo` 命令卡住 | 在等密码 | 输入密码时终端不显示字符，直接输入后回车即可 |

## 十四、附录：配置国内软件源（可选）

**只有下载明显缓慢或超时的同学才需要做这一节。** 官方源能正常下载时，整节跳过即可，不影响 Lab1 的任何验收项。做之前请先确认第七节的联网检查是通的。

### 为什么要做这一步

Ubuntu 默认从官方源（`archive.ubuntu.com`）下载软件包。在中国大陆访问官方源经常很慢，甚至连接超时，会导致后面的 `sudo apt update` 和 `sudo apt install` 长时间卡住或直接失败。把软件源换成国内镜像站之后，下载速度通常有明显提升。

本节以**清华大学开源软件镜像站（TUNA）**为例。

### 步骤 1：备份原有配置

Ubuntu 24.04 的软件源配置文件是 `/etc/apt/sources.list.d/ubuntu.sources`，采用新的 DEB822 格式，不再使用旧版的 `/etc/apt/sources.list`。网上很多针对 Ubuntu 22.04 及更早版本的换源教程改的是旧文件，在 24.04 上改了不生效。

先备份：

```bash
sudo cp /etc/apt/sources.list.d/ubuntu.sources /etc/apt/sources.list.d/ubuntu.sources.bak
```

如果后面配置写错了，用这条命令还原：

```bash
sudo cp /etc/apt/sources.list.d/ubuntu.sources.bak /etc/apt/sources.list.d/ubuntu.sources
```

### 步骤 2：写入清华镜像源

把下面**整段内容**复制粘贴到终端后按回车。注意要从第一行的 `sudo tee` 一直复制到最后一行的 `EOF`，中间不能漏行：

```bash
sudo tee /etc/apt/sources.list.d/ubuntu.sources > /dev/null <<'EOF'
Types: deb
URIs: https://mirrors.tuna.tsinghua.edu.cn/ubuntu
Suites: noble noble-updates noble-backports
Components: main restricted universe multiverse
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg

Types: deb
URIs: https://mirrors.tuna.tsinghua.edu.cn/ubuntu
Suites: noble-security
Components: main restricted universe multiverse
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg
EOF
```

说明：

- `noble` 是 Ubuntu 24.04 的代号。如果你装的是其他版本的 Ubuntu，必须把 `noble` 换成对应代号，否则更新时会报找不到软件源。
- `Signed-By` 指向系统自带的官方签名密钥，用于校验从镜像站下载的软件包，不要删除这一行。

### 步骤 3：确认写入的内容

```bash
cat /etc/apt/sources.list.d/ubuntu.sources
```

输出应与上一步粘贴的内容一致，`URIs` 两行都指向 `mirrors.tuna.tsinghua.edu.cn`。

### 步骤 4：刷新软件包索引

```bash
sudo apt update
```

正常时输出中的 `Get:` 行都来自 `mirrors.tuna.tsinghua.edu.cn`，最后显示读取完成，并且没有 `Err:`、`Failed` 或 `Could not resolve` 之类的错误。

### 备用镜像站

如果清华源当时较慢或无法访问，可以把上面命令中的 `URIs` 换成下面任意一个，其余内容保持不变：

| 镜像站 | `URIs` 填写值 |
| :--- | :--- |
| 清华大学 TUNA | `https://mirrors.tuna.tsinghua.edu.cn/ubuntu` |
| 阿里云 | `https://mirrors.aliyun.com/ubuntu` |
| 中国科学技术大学 | `https://mirrors.ustc.edu.cn/ubuntu` |
